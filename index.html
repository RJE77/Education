03 / Troubleshooting notes

Problems traced to their cause

  1. Ubuntu received IPv6 but no IPv4 lease

    Checked its VirtualBox network attachment and moved the client onto the same internal network as the OPNsense LAN. It later received 192.168.50.106.

  2. PXE-Test showed a black screen with UEFI

    Changed the virtual machine to one vCPU. It subsequently displayed Windows Boot Manager, loaded WinPE, and reached the command prompt.

  3. WinPE could not use the physical USB as one FAT32 volume

    Separated boot files and the larger Windows image into FAT32 and NTFS partitions, then verified the image was visible from WinPE on the laptop.

Routing project / October 12, 2026

OSPF routing and a tested backup path

Built a Cisco Packet Tracer network with three 2911 routers, two 2960 switches, and two PCs. Configured separate LAN and transit subnets, established OSPF neighbors in area 0, and verified that the PCs could still communicate after the direct router link was disabled.

Static routing

Established paths in both directions

Assigned interface addresses and PC default gateways, enabled router ports, and tested each local link. Diagnosed destination-host-unreachable messages by inspecting routing tables. Added static routes for the opposite LAN and its return path, then verified PC-to-PC ping.

Dynamic routing

Replaced static routes with OSPF

Enabled OSPF process 1 in area 0 using network statements and wildcard masks. Verified FULL neighbor states, removed the static routes, and confirmed remote LAN entries marked O in the routing tables.

Resilience test

Verified the alternate route

Added a middle router and two new transit networks. Corrected missing interface addresses and enabled the outer routers' new ports. After both new OSPF neighbors formed, shut down R1's direct link to R2: the PC-to-PC ping still received replies through the middle router.

Packet analysis / Learning in progress

Wireshark: connect symptoms to packet evidence

I am learning Wireshark on my desktop through video study and practice. My current focus is selecting the right capture adapter, filtering traffic, and explaining what DNS, ARP, and ICMP packets reveal about connectivity.

Name resolution

Follow a DNS exchange

Practice finding a query and its matching response with the dns display filter. Compare a successful lookup with repeated queries that have no visible answer.

Local delivery

Understand ARP and the gateway

Use arp to examine local address resolution. For an off-subnet destination, identify why the client needs the gateway’s MAC address.

Connectivity

Compare ping requests and replies

Use icmp to match echo requests and replies. Separate direct-IP reachability from name resolution, and avoid drawing conclusions beyond the evidence.

Interactive teaching example: Filter a synthetic packet trace, inspect individual packets, and compare successful DNS with an unanswered query. This demonstration is simulated and does not represent a completed capture from my lab.
